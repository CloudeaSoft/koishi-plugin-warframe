# 紫卡 OCR 解析与样本验证

## 当前流程

图片下载后调用腾讯云 `GeneralAccurateOCR`，保留文本、置信度和矩形坐标，再交给领域解析器。无需增加 OCR 服务或模型依赖。

- 依据相对坐标恢复同行碎片，不依赖供应商数组顺序或固定分辨率。部分块有坐标、部分缺失时拒绝解析，避免退回错误顺序后漏读属性。
- 武器名从现有武器词库中匹配；拉丁紫卡名称只接受官方导出的前后缀词段，忽略标题前无关的卡框装饰。
- 锁定图标被误读成前置 `6`、冲击图标被误读成“入/人”时，按受限规则处理。属性文字优先完整匹配，再考虑有唯一候选的纠错。
- 对“弓类武器效果加倍”“重击时 x2”等说明合并换行，包括下一行以 `x2)` 或 `2)` 开头的情况。只在拼接后构成完整的已知括号说明时合并，数值始终取属性本身。
- 同行数值和名称分离时，可以根据坐标重新组合。只有夹在两者之间、字号明显较小的无符号百分比才视为浮层；存在竞争数值则拒绝，不把数字拼成新值。
- 遮挡后留下至少三个汉字的词条后缀，只在坐标证明属于同一行且词库候选唯一时恢复。不推测被遮住的数字或正负号。
- “投射物速度”作为“投射物飞行速度”的明确别名处理，不放宽其他词条的模糊匹配。
- 页脚洗练次数上方的鼠标指针可能被识别为单个汉字。仅在置信度低于 60、尺寸不大于页脚文字、紧邻段位行且与右侧数字区域对齐时过滤；无坐标、缺少段位或计数、数字及属性片段仍保留校验。
- 未处理的属性片段、缺失数字、重复词条、名称歧义、多标题或数值符号残留均导致解析失败，不返回缺少属性的评分。

`parseOCRResult` 继续支持旧的 `string[]` 输入，也接受 `OcrTextBlock[]`。纯文本输入无法利用几何关系恢复遮挡碎片；实际图片链路使用结构化块。为兼容历史文本记录，旧字符串中的无符号数值仍可解析；结构化 OCR 缺少属性符号时会拒绝。

OCR 密钥在调用前去除首尾空白，避免粘贴配置中的换行导致签名失败。外层配置不被修改，密钥不写入样本或日志。

## 2026-10-21 独立中文样本评测（12 张、43 条）

按用户提供的 `rivens.json` 逐字段核对，12 张原图的 SHA-256 全部匹配。实际调用腾讯 `GeneralAccurateOCR` 后直接运行 `parseOCRResult`，未调用评分函数、武器变体推断或倾向数值范围校验。词条按属性身份核对，允许“暴击率／暴击几率”“弹药最大值／弹药上限”等同义名称。

- 完整解析正确：**9/12 张（75%）**，返回 **31/43 条**正确词条，没有成功返回但字段错误的样本。
- 另外 3 张整卡拒绝解析，12 条属性未返回，不能计入解析成功。

### 重击说明换行修复后的验证

解析器现在按完整的已知括号说明判断能否合并下一行，允许 `重击时` / `x2)`、`重击时x` / `2)` 等断行，不把说明中的 `2` 当作新属性数值。未知说明、残留数字和相邻的真实属性仍拒绝解析。

录制数据回放结果为 **10/10 张通过，35/35 条词条身份、数值、正负号与单位正确**。战刃原图另行重新调用腾讯 OCR，正确解析 `+17` 初始连击、`+65.4%` 暴击伤害、`+142%` 暴击几率和 `-77.4%` 处决伤害。全程不调用评分或倾向范围校验；结果与新 OCR 返回保存为 `verification-after-fix.json`。

`tests/services/wf/rivenOcr.community.spec.ts` 回放这 10 张图，并覆盖中英文说明断行、真实词条不能被吞掉以及旧百分比格式仍拒绝的反例。修复前先运行并确认战刃及断行说明用例失败，修复后通过。
