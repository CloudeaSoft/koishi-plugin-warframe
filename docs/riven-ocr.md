# 紫卡 OCR 解析与样本验证

## 当前流程

图片下载后调用腾讯云 `GeneralAccurateOCR`，保留文本、置信度和矩形坐标，再交给领域解析器。无需增加 OCR 服务或模型依赖。

- 依据相对坐标恢复同行碎片，不依赖供应商数组顺序或固定分辨率。部分块有坐标、部分缺失时拒绝解析，避免退回错误顺序后漏读属性。
- 武器名从现有武器词库中匹配；拉丁紫卡名称只接受官方导出的前后缀词段，忽略标题前无关的卡框装饰。
- 锁定图标被误读成前置 `6`、冲击图标被误读成“入/人”时，按受限规则处理。属性文字优先完整匹配，再考虑有唯一候选的纠错。
- 对“弓类武器效果加倍”“重击时 x2”等说明合并换行，数值始终取属性本身。
- 同行数值和名称分离时，可以根据坐标重新组合。只有夹在两者之间、字号明显较小的无符号百分比才视为浮层；存在竞争数值则拒绝，不把数字拼成新值。
- 遮挡后留下至少三个汉字的词条后缀，只在坐标证明属于同一行且词库候选唯一时恢复。不推测被遮住的数字或正负号。
- 未处理的属性片段、缺失数字、重复词条、名称歧义、多标题或数值符号残留均导致解析失败，不返回缺少属性的评分。

`parseOCRResult` 继续支持旧的 `string[]` 输入，也接受 `OcrTextBlock[]`。纯文本输入无法利用几何关系恢复遮挡碎片；实际图片链路使用结构化块。为兼容历史文本记录，旧字符串中的无符号数值仍可解析；结构化 OCR 缺少属性符号时会拒绝。

OCR 密钥在调用前去除首尾空白，避免粘贴配置中的换行导致签名失败。外层配置不被修改，密钥不写入样本或日志。

## 2026-10-19 样本结果

使用用户提供的 9 张图片和仓库已有的 11 张图片，实际调用腾讯 OCR；通过本地只读图片端点走 `getAnalyzedRiven` 的下载、OCR、解析和评分完整链路。另以同批录制文本回放修改前的解析器。

“完全正确”要求武器名、每条属性身份、数值和符号全部与人工核对结果一致，不能仅依据返回成功或属性数量判断。

| 样本 | 修改前逐字段正确 | 修改后逐字段正确 | 修改后完整链路成功 |
| --- | ---: | ---: | ---: |
| 新提供图片 | 4 / 9 | 9 / 9 | 9 / 9 |
| 仓库已有图片 | 5 / 11 | 11 / 11 | 11 / 11 |
| 合计 | 9 / 20 | 20 / 20 | 20 / 20 |

新图片主要覆盖以下情况：

| 图片 | 已验证的异常 |
| --- | --- |
| 1 | 冲击图标被识别为“入”，攻击范围无百分号 |
| 2 | “173%”浮层、数值与“态伤害”分离、`Infested` 漏字 |
| 3 | 元素图标与阵营乘数 |
| 4 | 锁定属性与射速说明换行 |
| 5 | 元素图标、说明换行、负面阵营乘数 |
| 6 | “173%”浮层、状态伤害及负变焦碎片分离 |
| 7 | 换行标题与三正一负属性 |
| 8 | 锁图标被识别成 `6+111.4%` |
| 9 | 锁图标被识别成 `6+105%`、腐蚀融合词条 |

样本 6 的霰弹枪负变焦在当前生成元数据中被禁用，但图片确实存在该属性。因此仅在已有卡片分析时兼容负变焦，并附参考范围说明；不启用正变焦，也不修改可洗词条列表。融合属性仍沿用原有“继承方式未验证”的范围提示。

## 回归素材与验证

- `tests/assets/riven-ocr/corpus.json`：20 份文本、置信度、坐标、图片 SHA-256 及人工核对字段；不含密钥或请求标识。
- 同目录 `image-1.png` 至 `image-9.png`：用户提供的原图；其余图片引用已有 `tests/assets/test-riven*.png`。
- `tests/services/wf/rivenOcr.wf.spec.ts`：逐字段断言及歧义、残缺、多卡、混合坐标等反例。
- `tests/services/wf/rivenOcr.integration.spec.ts`：仅替换外部图片下载和 SDK 响应，运行真实适配、解析与评分。
- `tests/infrastructure/ocr.infra.spec.ts`：坐标保留、密钥空白、空响应和网络失败。

离线回归不消耗 OCR 额度：

```sh
yarn build
yarn vitest run tests/services/wf/rivenOcr.wf.spec.ts tests/services/wf/rivenOcr.integration.spec.ts tests/infrastructure/ocr.infra.spec.ts
```

完整检查顺序为 `yarn build`、`yarn dtsc`、`yarn lint`、`yarn test`。

这 20 张图片也是本轮规则开发使用的样本，结果不能视为未见图片上的准确率。当前没有第二 OCR 引擎、图像增强或模型微调；完全遮挡的数字，以及 OCR 错读后仍呈现为合法数值的情况，无法仅靠本解析器可靠恢复。
